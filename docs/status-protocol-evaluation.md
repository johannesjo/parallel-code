# Agent status protocol evaluation

Updated 2026-11-19. **Adopt OSC 7501; don't invent a protocol.** Parallel Code now reads the [Program Status Protocol](https://www.superlogical.com/rex/docs/build/program-status) (OSC 7501, rev 0.3) from launches that have no lifecycle hooks (step 1 below). Next is a hook adapter for Copilot CLI, then Kimi and Droid on the same path. OSC 9/777 and ACP are deferred.

Confidence is about 85%. The open question the first version had, whether Claude Code sends OSC 7501 inside Parallel Code's terminal, is settled: Claude Code 2.1.328 asks with `OSC 7501;?`, sends nothing when the terminal stays silent, and reports once the terminal answers. In real turns it sent `working` then `done`, `blocked` with `kind=permission` at an approval dialog and `kind=question` at a multiple-choice question, each with a readable `msg`, and `idle` after Esc. That recorded session is a test in `program-status.test.ts`. The main uncertainty left is how reliably agents other than Claude will end a turn with `idle` or `done`; see the limits below.

Sources: **[R]** means read directly in source, docs or release notes. **[S]** means seen only in a search snippet.

## What was built (step 1)

- `electron/agent-hooks/program-status.ts` parses reports to the spec's validation rules, keeps the nested records (`id=lead/worker`) and reduces them to one hook-status update: blocked beats error beats working beats done. `blocked` maps to waiting with `prompt` permission or question, `error` to `StopFailure`, `done` to `Stop`, and `idle` to ready. A child record still working under a finished root is reported as background work, so the task stays working.
- The per-PTY terminal copy (`electron/ipc/terminal-query-responder.ts`) handles OSC 7501, answers the `?` query, and treats a full reset (RIS) as clearing every record. Replayed scrollback is ignored.
- `electron/ipc/pty.ts` enables it only for agent launches that got no hooks, so a hooked Claude or Codex never sees support and cannot report twice. In practice that is Claude in Docker, Claude under a wrapper not named `claude` or with the user's own `--settings`, and any custom agent or script that prints the sequence. `docs/custom-agents.md` has the `printf` line.

Limits, accepted for now:

- **A turn that never reports its end stays working.** Once an agent reports, the coordinator waits for a report rather than the screen, as it does for hooks. Claude keeps its existing silence fallback; other programs must send `idle` or `done`, and a stuck `working` ends when the process exits. A `working` not re-sent for 30 minutes is dropped, like a hook report, and the screen guessing takes over; the protocol has no heartbeat, so long turns without progress reports lose their status.
- **Typed keys count as evidence**, as for Claude: Esc or Ctrl-C during `working` reads as an interrupt, and Enter or a digit at a permission prompt as an approval, until the next report.
- **A child `error` or `blocked` record outranks the lead** until it is replaced or cleared. That follows the spec for `error`; a `blocked` worker that quits without clearing keeps the task in Needs you until the program exits.
- **`kind=auth`** shows as waiting for an answer; there is no sign-in state yet.
- **OSC 133 A** (a new shell prompt) does not drop working records; only agent launches, not shells, read reports.

Corrections to the brief:

- **OSC 7501 is not cmux's own format.** It is the published "Program Status Protocol" rev 0.3: states idle/working/done/blocked/error/clear, plus `kind=permission|question|auth` for blocked [R].
- **Warp's "structured notifications"** are OSC 777 with the title `warp://cli-agent` and a JSON body [R]. The JSON includes `background_task_count`. For most agents the sender is a plugin maintained by Warp or the community, not the agent itself [R].
- **herdr dropped its Codex hooks for a different reason.** The hooks were a stopgap while its screen detection was broken, and "dropped hook reports can still leave stale status". I found nothing about timeout warnings [R].
- **The false "done"/"running" with background sub-agents was real in cmux.** It was fixed in its hook layer (PRs #20346 and #25607) [R], not by the OSC data. ACP v2 and Warp each added a "background work" field for the same reason.

## 4. Recommendation

No agent-agnostic protocol covers the agents users actually run today. Only Claude Code sends OSC 7501 by itself, OSC 9/777 is free text, and ACP replaces the terminal. The ecosystem has instead converged on Claude-style hooks, which the existing pipeline already understands.

1. **First step (S):** an OSC 7501 receiver in the per-PTY terminal copy. It feeds a new status source ranked below hooks and above the guessing. It answers the `?` query so programs can detect support. Document a one-line `printf` for custom agents and wrapper scripts.
2. **Next (M):** a hook adapter for Copilot CLI. It is built in, has the best hooks, and currently gets only guessing. Then Kimi (#109) and Droid on the same path.
3. **Defer:** OSC 9/777, unless it is read in the same parser as a hint. Don't fake Warp's environment variables. ACP stays as the spike decided.

Tests a build needs (step 1 tests the parser, the records, the hook gate and replay; the missing-Stop and error-display paths reuse the hook handling and its existing tests, and the silence fallback for agents other than Claude and the opt-in smoke test are not built):

- **Parser:** both terminators, unknown state drops the whole report, `msg` is base64 and gets cleaned, 4096-byte cap, OSC 9;4 ignored, reports from a previous launch ignored.
- **Missing Stop:** a `working` report followed by silence or a redrawn prompt, an Esc interrupt, and the process exiting all settle without getting stuck on "working".
- **Background sub-agent:** with Claude hooks reporting background work, a 7501 `done` must not end "working". A launch that has hooks ignores 7501 state.
- **Approval vs question vs idle:** blocked+permission allows an approval keystroke, blocked+question does not, done/idle reads as ready, and error shows as the task's error state.
- **Real-agent smoke test (opt-in):** Claude in Docker mode shows status through 7501.
